## Design contracts

### ConnectionProfiles (new RefCounted)
`new(path="user://connection_profiles.json")`; `load_from(path="") -> Dictionary`, `save_to(path="") -> Dictionary`, `list_profiles() -> Array`, `add_profile(title,host,port,backend_url) -> Dictionary`, `update_profile(id,fields) -> Dictionary`, `remove_profile(id) -> Dictionary`, `remember_success(host,port,backend_url) -> Dictionary`, `last_success() -> Dictionary`.
Results `{ok:bool,reason:String,id?:String}`; caller owns persistence decision. Return deep copies. Strict JSON schema version1; max20 profiles; max64KiB file; title max48 chars; host max253; backend URL max2048. Random lowercase hex32 IDs. Reject control characters, unsupported URL schemes, invalid ports; accept localhost/DNS/IPv4/IPv6. No token/server_key/device_id in profile file. Atomic sibling temporary write+rename. Invalid load leaves old state unchanged. last_success stores endpoint only, not sensitive session data. Configurable path makes all tests temporary.

### GuestIdentity (new RefCounted)
`load_or_create(path="user://guest_id.txt") -> Dictionary {ok,reason,id}`; bounded read and strict non-control ID checks; stable valid ID; atomic creation/recovery; caller may choose ephemeral use only with explicit visible warning. CLI guest-id bypasses persistence.

### Backend menu hooks (root integration)
Preserve existing `connect_game(host:String)` and `selected_port()` contracts. Add `retry_requested`, `present_game_connection(status:Dictionary)`, `record_connection_success(host:String,port:int)`; the latter derives selected backend URL and calls remember_success only after synchronized. Add profile store injectable before `_ready` or via `setup_profiles(store)` to avoid test writes into user data. Keep gameplay connect separate from Nakama login/lobby; success of Nakama join never grants gameplay authority.
Root: wire retry_requested to existing game retry; call present_game_connection from client status updates; call record_connection_success only on authoritative snapshot completion. No auto-retry loops added by menu.

### Lobby hooks (root integration)
Preserve existing ready/name/rematch/disconnect signals. Add `retry_requested`, `present_connection(status:Dictionary)` and `operation_rejected(reason:String)`; `present` roster remains authoritative. Pending requests expire after bounded UI timeout and never alter own_ready/own_vote optimistically. Reset pending on new generation/disconnect. Disconnect confirmation has no transport side effects before confirm.

### Nakama client
Preserve public async return shapes: guest_login/connect_socket/find_match/cancel -> bool; request/create/join -> Dictionary. Add explicit validated endpoint setter; `close` cancels HTTP/socket and increments operation generation. Separate generation for auth ensures old callback cannot overwrite new login. Single current HTTP request; response-body cap. Bounded packet draining and active CID table. Validate nested response shapes before typed assignments. send failure immediately resolves request. No refresh-token implementation or auth role change in this scope.

### MatchClient
Preserve signals and runner semantics. Add `status_snapshot() -> Dictionary` containing state, host,port, phase,progress,latency_ms,last_error,can_retry (no resume token). `leave()/forget_resume()` makes explicit permanent departure; close retains existing retry behavior. `_send` returns Error/bool but existing callers may ignore. Connect validates before close. Packet source must be server peer1.
Synchronization clocks: overall attempt started once per recovery episode; activity deadline refreshed only by valid unique chunks; retries coalesced with cap/backoff and never reset overall deadline. Known old transfer_id chunk/end ignored, malformed current transfer recovers. Final valid end atomically swaps staging into runner as before. Last known good runner remains intact on errors.

### ServerRuntimeOptions (new RefCounted)
Typed defaults for reservation/hello/overall transfer limits and packet/byte budgets; `validate(candidate)`, `apply(candidate)` atomically. MatchServer `apply_options(dict)->Dictionary` only before active start. Existing start signature retained. Root may later supply CLI fields via GameConfig; this batch does not edit shared CLI parser. Hard upper bounds remain even if configured values are high.

### Snapshot queue
Per peer at most one active transfer; immutable frozen snapshot data/config/state/checksum/revisions. Queue scheduling uses global bounded chunks/bytes per process frame, round robin peers; snapshot begin/chunks/end order preserved. Disconnect/restart/rematch/close abort old transfer. A shot during transfer cannot mutate frozen snapshot; subsequent state/result messages must be ordered after snapshot end or cause explicit superseding transfer so clients never miss authoritative changes. This ordering is required and should be tested, not assumed. Bounded pending delta/state backlog; overflow restarts newest snapshot rather than unbounded buffering. `_send` checks packet result; failed transfer never emits successful end.

### Server lifecycle/diagnostics
`diagnostic_snapshot()` returns safe copy with uptime/phase/counts/counters/queue depths. `ServerMain.request_shutdown(reason)` enters existing grace shutdown then quits after bounded grace; duplicate calls harmless. Native application close notification uses same path. OS signal bridging and new CLI flags are root-owned hooks; do not pretend Godot handles POSIX SIGTERM automatically. Diagnostic JSON emitted only on explicit configured request/hook, not per frame. Tokens and client IPs excluded.
