# TerraBlast next250 Implementation Plan

> Use domain execution with tests, then independent cross-domain review. User preapproved implementation, commit and push.

**Goal:** Deliver250 concrete improvements: Arena Workshop, local competitions, spectators/chat, replay studio and simulation matrices.
**Architecture:** Five isolated modules reuse purecore, authoritative transport and unchanged archivecodecs. Root integrates shared scene/config/CLI.
**Tech Stack:** Godot4.6.2, GDScript, Python>=3.10stdlib, ENet, existing Nakama.
**Spec:** ../specs/2026-10-19-next-250-design.md

## Global constraints
- Preserve existing Rules/Weapon exported fields, v1/v2 exact replay and SessionStore.
- Network gameplay authority remains server-only; spectator defaults off.
- Limit all imported data, histories, files and subprocess work before mutation.
- Tests never write normal user preferences or archives.
- All250 IDs and acceptance criteria tracked in next-250-tasks.json.

## Review focus
- Returning from workshop/competition/studio must restore original runner/recorder/velocities without leaked autosaves/results.
- Late network/dialog callbacks may not affect replacement sessions.
- Untrusted JSON/ZIP/report paths never redirect writes or commands.
- Pause/focus/keyboard shortcuts do not bypass modal guards.
- Resume/cancel/deadline preserve consistent state and bounded resource usage.
