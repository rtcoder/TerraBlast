# TerraBlast second package of 50 — preapproved design

Extend the tested desktop prototype without changing Godot/GDScript, authoritative ENet architecture or RMB/LMB controls. User preapproved scope selection, implementation, verification, commit and local main integration; no remote publication.

Four independent areas: core match diagnostics/rules/replay; network state fidelity/lifecycle; portable tools/CLI/CI; client match controls/accessibility. Existing actionable backlog TB82 and TB83 plus48 new issues; placeholder TB60 excluded. Deliverables must each carry a concrete test, not merely scaffolding.

Interfaces: MatchFactory.create_match(player_limit=10,map_path=default,preset="classic"); runner.statistics dictionary and runner.history array, reset clears, state_snapshot includes them; runner.surrender(id)->result dictionary. Rules add max_turns (0 unlimited), wind (float X acceleration). Classic preserves current defaults. ReplayArchive.save(path,recorder,runner)->Error and load_verified(path)->Dictionary with ok/reason/runner; bounded JSON and expected hash. Shared VoxelRaycast first_solid(world,origin,direction,materials,max_distance=120)->Vector3i.

Network snapshots transfer validated rules/weapons/stats/history atomically. Transport exposes match_phase, latency_ms, snapshot_progress and surrender() plus graceful_shutdown(); start(port,map_path,preset). Unknown or inconsistent data never partially mutates published state.

Client F5 setup / P pause / F6 help are local overlays; network never pauses authoritative timers. Settings additions affect rendering only. New match recreates runner and renderer safely; all overlay openings cancel charge. Core changes are usable without UI.

Tools resolve repository paths from script location and Godot from GODOT_BIN/PATH/platform fallback, never eval user input. CLI help/version/list-maps/replay modes do not load gameplay scenes. Exports are configuration deliverables; do not claim cross-platform binaries without templates and actual builds.
